YouTubeは `yt-dlp` で字幕のみを取得した。多言語字幕の一括取得ではHTTP 429が発生したため、2本目は `en-orig` に絞って取得できた。1本目には投稿者字幕がなく、取得した自動字幕は内容不足だった。字幕から分からない画面操作の詳細は確認済みと扱っていない。字幕原文と一時メタデータは調査用の `/tmp/heptabase-tutor-research/` にあり、配布物には含めない。

以下は本スキル独自の設計判断であり、Heptabase製品の仕様だと主張するものではない。

- Markdownを両ツール共通の継続記録にする。
- 「扱った範囲」と「解答で示された理解」を別に記録する。
- 次回の最初の行動と回答待ちの問題をそのまま保存する。
- 未読資料・字幕の欠落を明示し、推測で補わない。
- 小さな行動と時間の目安を提示し、学習者の返答を待つ。

スキル形式と導入先は [OpenAI公式資料](https://learn.chatgpt.com/docs/build-skills) と [Claude Code公式資料](https://code.claude.com/docs/en/skills) で確認した。共通の `name` / `description` frontmatterを使用し、Claude専用の引数展開やツール許可設定に依存させない。

追加要件：Heptabase MCP / NotebookLM MCPを任意の**入力元**として扱う。Heptabase接続の `concepts` マニュアルを実際に読み、カード種別・接続範囲・Space Instructionsを尊重する手順を反映した。NotebookLMはこのセッションでツールが公開されていないため特定実装のAPI名に依存せず、検索・一覧・本文取得・照会という実際の能力を確認する設計とした。両者とも入力指定だけでは外部保存を行わない。

本の執筆用の手法を、対話で進む継続学習に合わせて次のように変えた。

- 恐怖リストは第1章でまとめて外すのでなく、使う直前に外す。質問は増やさず推定して示す。
- 近道は付録で精算するのでなく、回収時期を予約し、再開時に回収する。
- 禁止語は学習者向けの教材だけで検査する。REVIEWに記録した本人の回答は検査しない。
- 「就这样」は毎回の決まり文句にしない。
- PDF組版と4部構成の目次は取り入れない。
