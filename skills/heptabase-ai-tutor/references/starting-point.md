# 現在地チェック

開始位置と、先に補う前提を決めるための対話。知識全体の正確な測定や、固定の点数・レベル認定として扱わない。

## 始め方

- 保存済みの実回答や成果物に、今回の目標に関係する根拠があれば使う。本人の経験・自信と、実回答で確かめた理解を区別する。
- 本人が希望していなければ「短く現在地を確かめる／そのまま始める」を選べるようにする。提案が不要なら選択を増やさない。
- 希望済みなら「どこから始めるかを決めるため、短い問いを一つずつ出します。分からない・途中で説明に切り替える、でも大丈夫です」と短く伝えて始める。
- 詳しく確かめたい場合は既知の希望時間・範囲を使う。未指定なら短い範囲案を示して始め、延々と続けない。問題数や往復数そのものを目標にしない。

## 問いと調整

1. 目標に直結し、背景に合った答えやすい具体問を一つ出す。用語の定義だけでなく、結果の予測、具体例の説明、小さな実演などで、考え方も確かめる。回答を受け取るまで次の問いや正解を出さない。
2. 自力回答と理由から、確認できた点・誤解・まだ確かめていない点を分ける。正答でも理由が不明なら短く尋ね、流暢さや自信だけで判断しない。
3. 次の問いは、学習順序を決めるうえで残る不確実さに合わせる。必要なら適用先を変える、前提へ戻る、別の関連項目を確かめる。正誤だけで難易度を上下させたり、一つの誤答で全体を初心者扱いしたりしない。
4. 分からない回答を受け入れ、同じ問いへの再挑戦を必須にしない。必要な補足やヒントは使ってよく、本人が説明を希望したら説明する。援助前後の回答を分け、説明直後の復唱を自力での理解と見なさない。判定はSKILL.md第5節に従う。

## 終了して学習へつなぐ

開始位置と先に補う前提が決まったら終了する。希望した時間・範囲に達したとき、負担が見えたとき、本人が終了・説明への切り替えを希望したときも終了し、残りは未確認とする。詳しい診断を希望している場合も、この終了条件を使う。

「値の取得は理由つきで説明できたので短く扱い、キーがない場合の扱いから始めます」のように、回答と計画の関係を短く伝える。シラバス作成は第3節へ、開始まで任されている場合や説明を求められた場合はそのまま学習へ進む。診断を一度で確定した能力評価にせず、その後の回答に応じて修正する。

## 記録と再開

`REVIEW.md` に問題・実回答・理由・援助の内容とタイミング、確認できた範囲・誤解・未確認事項、開始位置の判断根拠を残す。`PROGRESS.md` は既存のフェーズを使い、出題中は `awaiting_answer`、活動は「現在地チェック」とする。範囲・終了の目安・次に見極める点と、回答待ちの問題全文を残す。

コース化前も第1節の保存先規則を使い、指定がなければ作業フォルダの `learning/<course-slug>/` にこの2ファイルだけを作る。診断を再開するときも実回答と援助の履歴を引き継ぎ、保存した判断から次の問いまたは学習開始へ進む。計画を作成したら診断の根拠をリンクし、確認していない範囲まで省略・習得済みにしない。
