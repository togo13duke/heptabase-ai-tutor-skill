# 保存用テンプレート

必要な時点で必要なファイルだけ作る。山括弧の値を実際の内容に置き換える。未確認の個人情報や回答を創作しない。

```text
learning/<course-slug>/
  GOAL.md
  SYLLABUS.md
  SOURCES.md
  PROGRESS.md
  SHORTCUTS.md             # 簡略化したときだけ
  FLASHCARDS.md            # 求められたときだけ
  PASSPORT.md              # 修了時・まとめを求められたとき
  sources/                 # 必要なときだけ
  sessions/001/
    PLAN.md
    PART-01.md
    REVIEW.md              # チェック時に作成
    SUMMARY.md             # 終了・中断時に作成
  notes/                   # 洞察の保存を求められたときだけ
    INDEX.md
```

## GOAL.md

```markdown
# <コース名>
- 到達目標：<何を説明・判断・実行できるか>
- 到達確認課題：<観察可能な課題>
- 通し題材：<複数のPartで少しずつ作る、本人に身近で実際にある題材。なければ「未確認」>
- 背景・既知事項：<自己申告／実回答で確認／未確認を区別。現在地チェックをした場合はREVIEWへのリンクと開始位置の理由>
- 目的・利用場面：
- 1回の時間：
- 学習スタイル・言語：
- 対象外：
- 更新日：

## つまずきリスト
| 用語・記号・場面 | 一言で（あだ名） | 外すPart | 出どころ |
| --- | --- | --- | --- |
| <例：σ> | <ばらつきのものさし> | <T1.P2> | 本人 / 推定 |
```

「出どころ」は本人が挙げたか、チューターの推定かを区別する。推定は本人が修正できるよう案内する。

## SYLLABUS.md

```markdown
# シラバス
状態：draft / active / finished
順序の理由：

| ID | Topic / Part | 前提 | 到達目標・確認課題 | 目安時間 | 資料 | 進行 | 理解・根拠 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| T1.P1 | <題名> | <前提> | <課題> | <分> | S1 | not_started | unverified |

## 変更履歴
- <日付>：<変更と理由。既存IDは保つ>
```

## SOURCES.md

```markdown
# 資料一覧
| ID | タイトル | URL / パス | 取得日 | 言語 | 取得状態・読んだ範囲・制限 |
| --- | --- | --- | --- | --- | --- |
```

MCP入力では各資料にサービス名、取得したオブジェクト種別とID、親ノートブック/ホワイトボードID、本文/抜粋/照会結果の別、原出典を追記する。秘密情報・認証情報は保存しない。

## PROGRESS.md

```markdown
# 再開ポイント
- 更新日時：<タイムゾーン付き>
- コース状態：draft / active / paused / finished
- 現在：<Session / Topic / Part>
- フェーズ：planning / teaching / awaiting_answer / review / wrap_up
- 活動：<レッスン / 現在地チェック / 理解度テスト / 説明チェック / カード復習など>
- 教材を扱った範囲：
- 解答で確認した理解と根拠：
- 未確認・誤解：
- 回答待ち：<質問全文と選択肢、なければ「なし」>
- 出題位置・回答状況：<必要な場合だけ。第2問/全5問、回答1回・ヒント提示済みなど>
- 回答記録：<該当するREVIEW.mdへの相対リンク。まだなければ「なし」>
- 次の一手：<具体的行動>
- 次回読むファイル：<相対リンク>
- 次回読む資料区間：
- 復習候補：<任意。通知設定ではない>
```

複数行の問題は `回答待ち：` の次行以降を字下げし、コードブロックと選択肢をそのまま残す。`次の一手` には「第2問の再回答を評価。再度誤答なら正解・理由を説明して類題を一問」のように、再開時の扱いまで書く。

現在地チェックでは「範囲・終了の目安」と「次に見極める点」を必要な項目として追加する。総問題数が未定なら「第2問」のように記録する。コース化前はコース直下の `REVIEW.md` と `PROGRESS.md` だけでよく、コース化後も診断記録は移動せずリンクで参照する。REVIEWには自力回答と援助後の回答、確認できた範囲・誤解・未確認事項、開始位置の判断根拠を残す。未着手の教材でも、対応する到達目標を実回答で確認済みなら `not_started` と `demonstrated（根拠）` を併記できる。

テストだけならコース直下の `REVIEW.md` と `PROGRESS.md`、カード作成だけなら `FLASHCARDS.md` と `PROGRESS.md` で始められる。既存コースではそのセッションの `REVIEW.md` を使う。保存先を `PROGRESS.md` にリンクし、存在しないGOAL・SYLLABUSへのリンクや空の代替ファイルを作らない。

## SHORTCUTS.md

```markdown
# 近道の帳簿
簡略化はしてよい。誤りは教えない。省いたことはここで回収する。
| ID | 場所 | 省いたこと | 今は安全な理由・範囲 | 回収する時期 | 状態 |
| --- | --- | --- | --- | --- | --- |
| SC1 | T1.P2 | <省いた条件・特例・定義> | <このコースの範囲で間違えない理由> | <Part IDか条件> | open |
```

状態は `open` / `paid`。回収したら `paid` にし、回収したPart IDを「回収する時期」の列に追記する。本文では「（近道SC1）」のように参照する。

## FLASHCARDS.md

```markdown
# フラッシュカード
元にした資料：<ノート・教材への参照>
| # | 分類 | 表（問い） | 裏（答え） | 出典 |
| --- | --- | --- | --- | --- |
| 1 | 定義 / プロセス・手順 / よくある間違い | | | |
```

## PLAN.md / PART-01.md / REVIEW.md / SUMMARY.md

- PLAN：到達点、シラバスID、所要時間、各Partの目的・見出し。
- PART：学習者のためにすることを表す題名。つまずきの場面・役に立つ点、具体例（出典か「自作」）、概念（用語は4段階）、今は気にしなくてよいこと、誤解・適用限界、近道の参照、確認問題（正解は書かない）、資料の参照。
- REVIEW：問題（理解度テストなら番号と難易度）、本人の実回答（未回答ならその旨）、推定した誤解、フィードバック、ヒントの有無と回答回数、理解の判定根拠、再確認課題。自分の言葉での説明は、説明の要旨、止めた箇所と指摘、言い直しの結果を残す。
- SUMMARY：扱った内容、各Partへの相対リンク、要点、本人が示した理解、未確認事項、保存した洞察、次回予告。

進行と理解はSYLLABUSの各行が基準、直近の再開位置はPROGRESSが基準。両方を更新する際は保存後に読み返し、状態が食い違っていないか確認する。`scripts/check_course.py` はこれらの値・リンク・ID・近道の食い違いを機械的に検査する。値は上の英語の語をそのまま使う（理解の列は `demonstrated（根拠）` のように根拠を括弧で添えてよい）。
