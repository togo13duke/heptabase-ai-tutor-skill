# 任意のMCPを学習資料の入力に使う

MCPの有無で授業の進め方を変えない。学習記録は通常どおりローカル `learning/<course-slug>/` に保存する。MCP経由で資料を読む依頼は、ノート作成・資料追加・外部同期の依頼ではない。

## 入力経路を決める

| 指定された資料 | 行動 |
| --- | --- |
| ローカルファイル・普通のURL | その入力を使う。MCPの接続を求めない |
| Heptabaseのカードやボード | 利用可能なHeptabaseツールを探索して読む |
| NotebookLMのノートブックやソース | 利用可能なNotebookLMツールを探索して読む |
| 複数サービスの資料 | 指定範囲内で併用し、資料ごとに出自を残す |
| MCP入力を指定されたが未接続 | 利用不可を伝え、貼り付け・エクスポート・元URLなどの代替を提示する |

ツールの名前・引数・機能はMCP実装によって異なる。実際に公開されたツール説明とスキーマで、検索、一覧、本文取得、照会の能力を確認する。存在しないツール名を呼ばず、接続があるだけで読めたと見なさない。MCP設定変更や追加インストールはこの学習スキルの必須手順にしない。

資料が特定できるURL・ID・名前があれば探索し、同名候補が複数あれば必要な選択だけ聞く。リンクからIDを推測せず、検索結果やツールが返したIDを保持する。入力元を明示されていない通常学習で、接続済みの私的知識ベース全体を勝手に探索しない。

## Heptabase入力

- 接続のマニュアル・利用指示を先に確認する。`read_system_manual_page` を提供する実装なら `concepts`、続いて指定されたSpace Instructionsを読む。
- 指定カードを読み、ホワイトボードなら含まれるカードの一覧から学習に必要なものを読む。検索結果の抜粋だけを全文扱いしない。
- カードIDと種別を保持する。PDF、動画、Webカードは本文や字幕の実際に取得できた範囲だけ使う。必要な画像を見られなければ制限を記録する。
- 接続対象外のSpace・共有物やクライアント必須などの制限に従う。「見つからない」はその資料が存在しない証拠ではない。
- 学習資料を読むためにカード・ホワイトボードを作成したり、配置を変更したりしない。

## NotebookLM入力

1. 指定ノートブックを特定し、ソース一覧の名前・ID・取得状態を確認する。
2. ソース本文を読む機能があれば、今回の範囲の本文を優先する。巨大な資料は区間・上限を指定し、未読部分を記録する。
3. 照会機能しかない場合は、対象ソースを絞れるなら絞り、目的・用語・具体例について出典つきの回答を求める。返ったものを「NotebookLMによる回答」と明記し、元ソース本文を確認したとは言わない。
4. 回答の引用元・ソースID・位置を保持する。引用の裏付けが取得できなければ未検証と記録し、架空のページ番号やタイムスタンプを補わない。
5. 処理中のソースは、状態確認・待機機能があれば適切な間隔で待ち、準備完了後に読む。失敗・タイムアウト・権限不足は未取得として扱う。

この用途では新しいノートブック作成、ソース追加、既存ソースの削除、音声や動画生成は不要。読み取り用の照会がサービス側の履歴に残る可能性は実装の仕様に従うが、明示的な教材・ノートの書き込みは別依頼として扱う。

## 共通の出典と再開

`SOURCES.md` にサービス名、タイトル、親ID、ソース/カードID、ツールが返したURL、取得日時、読んだ範囲、本文/抜粋/照会結果の別、原出典との対応を記録する。URLが返らなければIDだけ記録し、リンクを捏造しない。

教材ではローカル資料と同じ資料ID（S1等）で参照する。複数サービスに同じ資料がある場合は同一URLや内容で重複を確認し、矛盾する版は分けて扱う。

次回はローカルの進捗から始め、必要な資料だけMCPで再取得する。切断時は取得済みの範囲を明示して継続できるが、キャッシュのない内容や更新後の内容を推測しない。新しい資料が必須なら入力を待ち、その間に別のTopicを勝手に完了させない。
