## 物語「谷向こうの写本」

山あいの村に、写字生のオトがいた。この冬の仕事は、谷を三つ越えた先の僧院へ、一冊の古い本をまるごと写して届けることだった。

本は一度には運べない。オトは写した頁を一枚ずつ封筒に入れ、使いに持たせて峠へ送り出した。封筒には必ず頁の番号を書いた。峠の道は何本にも分かれていて、先に出た使いより後の使いが先に着くこともある。番号があれば、僧院の司書ミナは、届いた順ではなく番号の順に綴じ直せる。

ミナは封筒を受け取ると、短い返事を書いて村へ送り返した。返事に書くのはいつも二つだけだった。「次は何頁目をください」と、「わたしの机には、あと何枚置けます」。

最初に困ったのは、頁が消えることだった。九頁目を送ったきり、いつまで待っても「次は十頁目を」が来ない。九頁目は峠のどこかで失われたらしい。

それからオトは、頁を送り出すたびに砂時計をひっくり返すようにした。砂が落ちきっても返事が来なければ、同じ頁をもう一度写して送る。そのために、返事が来るまでは手元の控えを捨てなかった。ミナのもとに同じ番号の頁が二枚届いても困らない。番号が同じなら、片方を捨てればよい。砂時計の長さは、使いがいつも何日で往復するかを見ながら決め直した。短すぎれば、まだ道の途中にある頁をむだに写し直すことになる。長すぎれば、消えた頁をいつまでも待つことになる。

次に困ったのは、オトの手が速くなってからだった。オトは返事を待たずに何枚も続けて送れるようになった。ところがミナの机は小さい。綴じる手が追いつかないうちに頁が次々届くと、置き場がなく、受け取れない頁は捨てるしかない。

そこでオトは、返事に書かれた二つ目の数を守ることにした。ミナが「あと三枚置けます」と書いてきたら、返事を待っている頁が三枚を超えないように送る。「あと〇枚」と書かれていたら送るのをやめ、ときどき「机は空きましたか」とだけ書いた小さな使いを出して確かめた。

三つ目の困りごとが、いちばんやっかいだった。峠はオトの村だけのものではない。ほかの村の使いも、同じ峠の同じ山小屋で休んで谷を渡る。小屋に入りきれないほど使いが集まると、あとから着いた使いの頁は、そこで捨てられてしまう。小屋には番人もいなければ、混み具合を知らせる鐘もない。ミナの机がどれほど空いていても、峠が詰まれば頁は消える。

オトは、峠の具合を自分で推し量ることにした。新しい本の最初は、一枚だけ送る。返事が無事に戻れば、次の一往復では二枚、その次は四枚と倍に増やす。前に頁が消えたときの半分ほどの枚数まで来たら、そこからは一往復ごとに一枚ずつだけ足す。そして砂時計が落ちきった日には、消えた頁を写し直して送ると同時に、一度に送る枚数を一枚に戻して、また数え直した。ほかの村の写字生たちも、同じやり方をしていた。だから峠は、誰に命じられたわけでもないのに、詰まりきらずにすんだ。

こうして、オトが返事を待たずに送ってよい枚数は、いつも二つの数のうち小さいほうになった。ミナの返事に書かれた机の空きと、自分で推し量った峠の具合である。

春になって、オトは弟子に仕事を教えた。新しい本を送り始める前には、まず僧院と三度あいさつを交わす。

「こちらの頁は、三百十二番から数えます」
「承知しました。こちらから送る手紙は、八百五番から数えます」
「承知しました」

弟子は首をかしげた。「どうして一番から数えないのですか」

オトは笑って、それはまた別の冬の話だ、と言った。

## 物語の後（学習者の推測を聞いてから出す）

推測を受けてから、以下の解説と確認問題を出す。推測の内容は REVIEW.md に記録する。

### 全体像

TCPの送り手は、三つの別々の心配を同時に抱えている。

- **届いたか**：届かなかった分を送り直す（再送）。
- **相手が受け止められるか**：受け手の置き場をあふれさせない（フロー制御）。
- **途中の道が詰まっていないか**：みんなで使う経路を詰まらせない（輻輳制御）。

三つは、一つの量でつながっている。「返事を待たずに送ってよい量」は、受け手が知らせてくる空き（受信ウィンドウ）と、送り手が自分で推し量る道の具合（輻輳ウィンドウ）の小さいほうになる。そして「頁が消えた」という一つの出来事が、再送のきっかけであり、同時に「道が詰まっているらしい」という輻輳制御の手がかりにもなる。

### 対応表

| 物語の要素（あだ名） | 一言の意味 | 正式名称 |
| --- | --- | --- |
| 頁の番号 | 順番を取り戻し、同じものが二度届いたら見分けるための札 | シーケンス番号 |
| 「次は何頁目をください」 | ここまでは届いた、次はここから、という知らせ | 確認応答（ACK）、ACK番号 |
| 砂時計 | 返事を待つ制限時間。往復時間を見て決め直す | 再送タイマー（RTO）、往復時間（RTT） |
| 同じ頁をもう一度写して送る | 届いた知らせが来ない分を送り直す | 再送 |
| 返事が来るまで控えを捨てない | 再送に備えて、送ったデータを手元に残しておく | 送信バッファ |
| ミナの机の空き「あと何枚置けます」 | 受け手がまだ受け止められる量 | 受信ウィンドウ（rwnd）→ フロー制御 |
| 「机は空きましたか」の小さな使い | 空き0と言われた後、空いたかを確かめる | ゼロウィンドウプローブ |
| 峠と山小屋 | みんなで共有する経路と、その途中の待合所 | ネットワーク経路、ルーターのキュー |
| 小屋に入りきれず頁が捨てられる | 混雑した中継点でデータが落とされる | パケット廃棄（パケットロス） |
| 一枚から倍々に増やす | 道の具合が分からないうちは小さく始めて急いで増やす | スロースタート |
| 半分ほどまで来たら一枚ずつ足す | 前に詰まったあたりからは慎重に増やす | 輻輳回避、スロースタート閾値（ssthresh） |
| オトが推し量る峠の具合 | 送り手が自分で見積もる、道に流してよい量 | 輻輳ウィンドウ（cwnd）→ 輻輳制御 |
| 二つの数の小さいほう | 実際に返事待ちにしてよい量 | 送信できる量 ＝ min(rwnd, cwnd) |
| 三度のあいさつ | 送り始める前に、互いの数え始めの番号を伝え合う | 3ウェイハンドシェイク、初期シーケンス番号 |

最後の「三度のあいさつ」は気づくための手がかりで、今回の三つの仕組みそのものではない（接続の確立）。

### 物語が通用しないところ

- **番号は頁ではなくバイトに付く。** 物語では一枚ごとに番号を付けたが、TCPは送るデータの1バイトごとに番号を数える。ACK番号も「次に欲しいバイトの番号」である（近道SC1）。
- **再送のきっかけは砂時計だけではない。** 実際のTCPでは、後の頁が届くたびに同じ「次は九頁目を」が繰り返し返ってくると（重複ACK）、砂時計を待たずに送り直す。このときは送る量を一枚まで戻さず、半分ほどに減らす。現在よく使われる方式では、増やし方もこの物語より複雑である（近道SC2）。
- **頁が消える理由は混雑だけとは限らない。** 無線の雑音などでも消えるが、古典的なTCPはそれを区別できず、混雑と見なして減らす。また、峠の小屋には「鐘がない」としたが、実際には中継点が混雑の印を付けて知らせる仕組み（ECN）もある（近道SC3）。

### 今は気にしなくてよいこと

- 砂時計の長さを決める具体的な計算式。再送が多すぎる・遅すぎる場面を調べるとき（T2.P2）に戻る。
- 「別の冬の話」（なぜ1から数えないのか）。接続の確立を学ぶときに扱う。

### 確認問題

物語に出てこない場面で考える。

ある社内サーバーから、夜だけ大きなファイルの転送が遅くなる。受け手の機械は余裕があり、返ってくるACKにはいつも大きな受信ウィンドウが書かれている。調べると、夜の時間帯にだけときどき再送が起きている。

このとき送り手にブレーキをかけているのは、フロー制御と輻輳制御のどちらか。そう考えた理由と、送り手は何を手がかりにブレーキをかけているかを一言で添えてください。
