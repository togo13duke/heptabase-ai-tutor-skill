「結合といえばINNER JOIN」という理由、よく分かります。いちばん最初に習う結合なので、頭に最初に浮かぶのは自然です。今回の問題は、その「いつもの選び方」がちょうど通用しない場面でした。

## ずれたところ

小さな表で見てみます（自作の例）。

顧客

| customer_id | name |
| --- | --- |
| 1 | 田中 |
| 2 | 佐藤 |
| 3 | 鈴木 |

注文

| order_id | customer_id |
| --- | --- |
| 101 | 1 |
| 102 | 1 |
| 103 | 2 |

鈴木さんは注文が0件です。

- **INNER JOIN**：両方の表で相手が見つかった行だけ残す。鈴木さんには相手がいないので、結果から消える。出てくるのは田中2件・佐藤1件だけで、「注文0件の顧客」は結果に現れない。
- **LEFT JOIN（顧客を左）**：左の表（顧客）の行は全部残す。相手がいなければ、注文側は空欄（NULL）で埋める。鈴木さんも1行残るので、件数を数えると0件として出せる。

問題文の「注文が1件もない顧客も含めて」は、「左の表の行を落とさない」という合図です。この一言があれば、INNER JOINは落とす側なので外れます。

INNER JOINが正解になるのは、「注文のある顧客だけでよい」「両方の表に対応があるものだけを見たい」場面です。
